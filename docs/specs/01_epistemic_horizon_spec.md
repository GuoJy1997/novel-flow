# 角色知情视界沙盒与防前知渗透规范 (Epistemic Horizon Specification)

> **版本**：v1.0  
> **适用范围**：`explore_context`（前置蒸馏）、`draft_chapter`（正文主笔）、`audit_persona`（人设知情审查）  
> **核心目标**：彻底消灭 AI 正文写作中的“上帝视角”、“对白偷看大纲”、“线索未卜先知”等信息早产硬伤。

---

## 一、 病理定义与反模式（Anti-Patterns）

在长篇悬疑与智斗小说创作中，以下行为被定义为**严重生产事故（一票否决）**：

1. **早产剧透（Premature Exposition）**：
   - 角色说出尚未调查清楚、尚未掉马甲的幕后黑手真实身份（例如：第 25 章提防刘弼是前燕特务）。
2. **上帝归纳（Omniscient Deduction）**：
   - 角色仅看到一个微弱线索，直接“顿悟”得出十步之后的完整案情，缺乏推理链条与试错成本。
3. **世界观词汇越界（Conceptual Bleeding）**：
   - 历史 NPC 突然说出现代概念，或本卷未公开的副本超自然机制（例如：在未显形前，NPC 意识到有“隐形人”；在丧尸爆发前，名士说出“丧尸/丧尸毒”）。

## 二、 物理隔离架构：知情视界沙盒（Epistemic Sandbox）

正文主笔节点（`draft_chapter`）**严禁直接挂载全书大纲或全卷大纲**。输入必须经过前置节点裁剪，降维为本章专属的《知情视界沙盒卡》。

```
                    【全卷大纲 / 伏笔总表 / 设定库】
                                   │
                                   ▼
              ┌─────────────────────────────────────────┐
              │ 节点: explore_context (知情视界裁决官)   │
              │ 职责: 针对第 N 章执行信息剥离与时间线过滤 │
              └─────────────────────────────────────────┘
                                   │
                         产物: 本章知情视界卡
                                   │
                                   ▼
                    ┌─────────────────────────────┐
                    │  节点: draft_chapter (主笔)  │
                    │  (仅能看到沙盒内允许的信息) │
                    └─────────────────────────────┘
                                   │
                                   ▼
                    ┌─────────────────────────────┐
                    │  节点: audit_persona (审查) │
                    │  (执行反向台词信息源核查)   │
                    └─────────────────────────────┘
```

## 三、 本章知情视界卡标准数据结构 (JSON / YAML)

每个出场人物在本章的知情状态必须严格划分为三档：

```yaml
chapter: 50
characters:
  顾君:
    knowns:
      - "已目击王羲之、谢安、桓温、殷浩四方在竹林齐聚"
      - "知晓桓温以假护卫身份在场，且其武力威压全场"
      - "知晓玉玺与召令大醮的真正关联（由王羲之道破）"
    suspects:
      - "推测谢安袖手旁观必定有政治弃子（怀疑会牺牲殷浩）"
      - "推测生门开启与玉玺的归属裁决直接绑定"
    forbidden_blindspots:
      - "严禁说出'刘弼未死'（此时刘弼被认为已诛）"
      - "严禁直接点破反派卢夏的现实阴谋全景"
      - "严禁说出禁忌词：一死生、齐彭殇、虚诞、妄作"

  桓温:
    knowns:
      - "全场已被自己亲兵封锁，自身掌握终极武力"
      - "朝廷软弱，殷浩北伐必败"
    suspects:
      - "怀疑谢安与王羲之暗通款曲护卫建康朝廷"
    forbidden_blindspots:
      - "绝不知道眼前十岁幼童王献之将在后世与顾君队伍产生因果绑定"
      - "不知道顾君等人的现代人真实来历"
```

## 四、 审查节点判定标准与断言规则

在 `audit_persona` 审查阶段，系统必须对正文所有对话与心理活动执行以下硬断言：

1. **台词溯源断言（Attribution Check）**：
   - 抽取每一句含有推论或事实指控的台词；
   - 检查该事实是否包含在说话者的 `knowns` 或 `suspects` 中；
   - **若命中 `forbidden_blindspots`，断言失败，扣 20 分，输出修改定位**。
2. **试错成本核查（Fallibility Check）**：
   - 智斗场景中，主角团队的推论在得到物证前，必须包含“假设”、“试探”或“误判可能性”，严禁 100% 盲猜命中。
