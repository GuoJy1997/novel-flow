# 单章纯净上下文剪裁与任务卡提炼指南 (Context Curator)

长篇连载最常见的工程误区是“把整本小说的世界观、几十个人物档案、十万字前文全部塞进 Prompt”。这会导致：
1. 大模型的注意力被稀释，忽略了本章的核心戏剧冲突；
2. 触发幻觉与时序混乱，让几万字之前死去的配角突然“借尸还魂”；
3. 严重的 API 延迟与 token 浪费。

本技能专用于 `gather_state`（前置状态盘点）节点，充当**极度严苛的上下文剪刀手**。

---

## 一、 上下文修剪的“三个凡是”原则

在为当前第 N 章生成 `工作区/第{N}章/01_状态上下文.md` 时：
1. **凡是本章不上场的人物，一律不塞入档案**：
   - 即使是第一女主角，只要本章场景发生在一个封闭密室且无远程通讯，就不放入她的外貌或心理档案；
2. **凡是与本章物理冲突无关的世界观法则，一律剔除**：
   - 本章写动力舱抢修，严禁拼入帝国外交制度、宗门历史渊源等无关软设定；
3. **凡是尚未到回收期的无关伏笔，一律不写入当前提示词**：
   - 避免模型为了“完成任务”而强行在不合适的场景提前把伏笔给剧透了。

---

## 二、 黄金单章任务上下文模板 (Strict Schema)

输出给后续 `draft_chapter` 节点的任务上下文，总字数必须严格控制在 **800 - 1500 字**，严格遵循以下紧凑结构：

```markdown
# 第 {N} 章执行任务上下文

## 1. 核心戏剧目标与时限压迫
- 主角即时目标：[在跃迁前 3 分钟内查出动力舱异常]
- 核心阻碍与对手：[林朔的阻拦与倒计时死线]
- 失败致命代价：[全舰被超空间引力撕碎]

## 2. 登场角色即时状态切片 (仅限现场人员)
- **陆巡 (POV)**：后颈芯片过载灼痛，左手微颤；知晓黑匣子有自己的录音，但未向任何人透露；极端冷静。
- **林朔**：持枪警惕状态；怀疑陆巡有自毁倾向；内心防备极高。

## 3. 必须遵守的物理/世界观硬边界
- 跃迁引擎锁死机制遵循《科技与灵能.md》第 2 条：物理齿轮卡死只能从排气阀外侧拆除。

## 4. 必须埋设/推进的伏笔动作
- 借修检之名，在控制台底部观察是否有军方特种焊锡痕迹。

## 5. 本章预期章末钩子方向
- 倒计时最后一秒，发现了动力舱地板下的一具新鲜尸体。
```

通过这种高压提炼，主笔写作节点拿到的全是纯净干货，出稿命中率可达 95% 以上！
